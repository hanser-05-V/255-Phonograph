# 255留音机本地曲库与音乐管理后台设计

## 1. 背景与目标

当前“255留音机”已经具备响应式首页、迷你播放器、完整播放器、播放控制、LRC 歌词同步、实时频谱、键盘快捷键和浏览器本地的今日听歌统计，但曲库仍由前端静态示例数据提供。

本阶段的目标是先完成可由项目所有者独立使用的网页版音乐管理闭环：在本机管理后台逐首上传和整理歌曲，由本地服务持久保存资料与媒体文件，普通首页、音乐馆和播放器共同读取同一份动态曲库。该设计同时为后续云端存储、公开账号、评论、故事会切片和 Android APK 留出清晰边界，但不提前实现这些功能。

## 2. 本阶段范围

### 2.1 包含内容

- 仅开发网页版。
- 新增本地 TypeScript 服务端、SQLite 曲库和项目外统一媒体数据目录。
- 新增仅管理员可访问的音乐管理后台。
- 支持歌曲草稿、发布、下架、恢复、回收站与永久删除流程。
- 支持单首音频上传、封面、LRC、分类、标签和可选来源资料。
- 新增独立音乐馆页面，并将首页和播放器接入动态曲库。
- 保留现有过渡歌曲，正式歌曲由项目所有者在功能完成后逐步上传并替换。
- 保留现有播放、歌词、频谱、快捷键、今日统计和响应式体验。
- 提供开发与本地正式使用的一键启动方式。

### 2.2 明确不包含

- 云端部署、域名、对象存储或云点播接入。
- Android APK 和 iOS 应用。
- 普通用户注册、GitHub 登录、邮箱验证码登录和 B站 UID 绑定。
- 评论、点赞、举报、账号合并、解绑和找回。
- 故事会切片上传、审核或详情页。
- 普通用户上传音乐。
- 批量导入、断点续传、音频转码和无损源文件处理。
- 管理密码找回或本机重置工具。
- 自动备份或一键恢复界面。
- 多用户并发和公开运营层面的扩容优化。

## 3. 角色与权限

本阶段只有两个访问层级：

- 普通访问：本机打开首页和音乐馆即可浏览、搜索和播放已发布歌曲，不要求登录。
- 管理访问：通过固定 `/admin` 地址进入；入口不出现在普通导航中。管理接口必须验证有效的管理会话。

首次访问管理后台时创建独立管理密码。密码使用安全哈希保存，不保存明文；登录成功后通过 HttpOnly、SameSite Cookie 维持管理会话。管理员可在已登录状态下修改密码。本阶段不提供忘记密码或找回流程。

## 4. 管理后台设计

### 4.1 页面与导航

管理后台包含：

- 首次设置与登录页。
- 歌曲列表页，可按状态查看草稿、已发布、已下架和回收站项目。
- 新建/编辑歌曲页。
- 分类与标签管理页。
- 回收站页。
- 基础设置区，用于修改管理密码并显示数据目录位置。

### 4.2 歌曲资料

发布歌曲时必须具备：

- 音频文件。
- 歌名。
- 歌手。
- 可被系统识别的歌曲时长。

以下字段可选，不影响发布：

- 封面。
- LRC 歌词。
- 分类。
- 一个或多个标签。
- 版本说明。
- 演唱日期。
- 来源链接。
- 是否进入“精选歌曲”。
- 是否进入“直播翻唱精选”。

每首歌曲最多选择一个分类，可以选择多个标签。分类和标签必须先在后台统一创建，再供歌曲选择，以避免重复项、同义词和错别字。

### 4.3 文件规则

- 音频仅支持 MP3、M4A，单文件最大 200 MB。
- 上传过程显示进度并允许取消。
- 上传失败后重新上传，不支持断点续传。
- 系统自动读取音频时长；无法识别时允许保留草稿，但不能发布。
- 封面支持 JPG、PNG、WebP，单文件最大 10 MB。
- 未上传封面时使用统一默认封面。
- LRC 既可上传 `.lrc` 文件，也可在文本框中粘贴和编辑。
- LRC 时间标签格式错误时允许保存草稿，但不能携带错误歌词发布；歌曲本身没有歌词时可以正常发布。

### 4.4 重复歌曲与编辑

同名歌曲允许存在，以支持不同现场或不同版本。当歌名和歌手都完全相同时，后台给出重复提醒并要求确认，但不强制阻止保存。

已发布歌曲可以直接修改歌名、歌手、封面、歌词、分类、标签和来源资料。替换音频文件时必须额外确认，但歌曲稳定编号保持不变，使未来评论、收藏和播放记录能够继续关联同一歌曲。

### 4.5 生命周期

歌曲状态包括：

1. 草稿：允许资料不完整，仅管理后台可见。
2. 已发布：在普通曲库、首页和播放器中可见。
3. 已下架：普通曲库不可见，管理后台可重新发布或移入回收站。
4. 回收站：等待恢复或永久删除，普通曲库不可见。

已发布歌曲不能一步永久删除。删除路径必须经过“下架 → 移入回收站 → 二次确认永久删除”。永久删除时才删除数据库业务记录和相关媒体文件。

## 5. 普通网页设计

### 5.1 首页

首页保持现有视觉方向、今日听歌概览、每日憨曲、每日一签入口、故事会预览和固定底部迷你播放器。

- 每个音乐分区最多展示 6 首歌曲，并提供进入音乐馆的入口。
- 新发布歌曲自动进入“最近加入”，按发布时间从新到旧排列。
- 后台勾选的歌曲进入“精选歌曲”或“直播翻唱精选”，同样按发布时间从新到旧排列。
- 本阶段不提供音乐分区手动排序。
- “每日憨曲”从全部已发布歌曲中按本地自然日稳定选择。
- 歌曲卡点击后直接通过共享播放器播放。
- 现有故事会预览保留；未开放的故事功能不创建空白详情页。

### 5.2 音乐馆

新增独立 `/music` 页面：

- 展示全部已发布歌曲。
- 支持按歌名搜索，不搜索歌手。
- 支持单个分类筛选和标签筛选。
- 无匹配结果时显示明确提示。
- 点击歌曲后立即切换并播放。

从搜索结果或筛选结果点击歌曲时，当前结果集合成为临时播放列表；上一首和下一首仅在该列表内循环。回到全部歌曲并从中播放后，恢复完整已发布曲库队列。

### 5.3 共享播放器

首页、音乐馆、歌曲卡、每日憨曲、迷你播放器和完整播放器必须共用一个 `PlayerProvider` 和一个 `HTMLAudioElement`。页面导航不得创建第二个播放器，也不得让页面组件直接修改音频地址。

动态曲库接入后，播放器继续提供现有播放、暂停、上一首、下一首、进度、音量、静音、自动续播、LRC 同步、实时频谱和键盘快捷键功能。

浏览器本地保存：

- 当前歌曲的稳定编号。
- 当前播放进度。
- 音量与静音状态。
- 当前临时播放列表的歌曲编号及顺序。

刷新或关闭后重新打开网页时恢复这些状态，但始终保持暂停，必须由用户手动点击后继续播放。恢复队列时移除已经下架或删除的歌曲；如果当前歌曲已失效，则选择当前曲库第一首并保持暂停。

### 5.4 今日统计

现有今日听歌统计继续使用浏览器本地数据并遵循现有规则：

- 跨本地自然日重置。
- 累计当天实际播放秒数。
- 一首歌曲当天播放超过 10 秒后计入听过歌曲数量，同一稳定歌曲编号只计一次。
- 憨浓度为 `min(100, round(累计播放秒数 / 3600 × 100))`。

接入动态曲库时使用稳定歌曲编号替代数组索引，并尽量保留升级当天已经累计的播放时间。

## 6. 技术架构

### 6.1 总体结构

推荐结构为：

- 现有 React/Vite 前端。
- 同仓库 TypeScript/Fastify 本地服务端。
- Node.js 24 自带的 SQLite 能力。
- 项目外统一数据目录。
- 可替换的媒体存储接口。

开发环境由一个命令同时启动 Vite 和本地服务端。本地正式使用也提供一个统一启动命令。数据库和媒体目录不存在时自动创建。

### 6.2 数据模型

核心数据包括：

- `songs`：稳定编号、标题、歌手、状态、时长、音频引用、封面引用、歌词引用或文本、分类、可选来源资料、首页分区标记、创建时间、更新时间和发布时间。
- `categories`：分类编号、名称、创建时间和更新时间。
- `tags`：标签编号、名称、创建时间和更新时间。
- `song_tags`：歌曲与标签的多对多关系。
- `admin_config`：管理密码哈希及首次设置状态。
- `admin_sessions`：管理会话摘要、有效期和失效状态。
- `pending_media_cleanup`：数据库记录已删除但文件清理失败时的待处理任务。

歌曲、分类和标签编号不可因重新排序或编辑而变化。已发布时间单独保存，供“最近加入”和其他首页分区稳定排序。

数据库结构变化采用受控版本升级脚本管理，脚本只包含结构与必要元数据，不包含数据库文件、媒体或迁移数据包。

### 6.3 存储层

媒体存储接口至少提供：

- 建立临时上传。
- 写入并报告进度。
- 校验后原子转为正式文件。
- 打开媒体流并支持字节范围读取。
- 删除媒体。
- 清理失效临时文件。

第一版实现本地目录适配器。文件使用随机且不可猜测的内部名称，原始文件名仅作为显示或审计资料，不直接作为磁盘路径。以后切换云对象存储时复用同一接口，不改变页面和播放器的数据结构。

上传取消、验证失败或业务保存失败时不得产生正式曲库记录，并清理临时文件。永久删除时先使数据库记录对普通接口不可见，再清理媒体；清理失败则写入待清理任务，不能让已删除歌曲重新出现。

### 6.4 服务接口

接口分为：

- 普通只读曲库接口：只返回已发布歌曲、分类、标签和首页分区数据。
- 媒体接口：根据受控媒体编号返回封面、歌词或支持 HTTP Range 的音频流，不暴露真实磁盘路径。
- 管理认证接口：首次设置、登录、退出和已登录状态下修改密码。
- 管理曲库接口：草稿、编辑、发布、下架、恢复、回收站和永久删除。
- 管理分类与标签接口。
- 上传接口：音频、封面和歌词文件上传、进度与取消。

所有管理写接口验证管理会话并校验输入。普通页面不直接读取数据库或本机目录。

### 6.5 过渡歌曲

首次初始化数据库时自动创建现有“初光”“等火山喷发的小星球”“夜行”等过渡歌曲记录，并在数据目录生成运行时示范音频。示范媒体不提交到 Git。项目所有者上传正式歌曲后，可通过正常的下架和回收站流程逐步替换过渡内容。

## 7. 状态同步与失败处理

- 前端先加载曲库，再建立播放器；加载期间显示明确状态。
- 本地服务未运行、接口请求失败、曲库为空和搜索无结果分别显示不同提示。
- 后台发布、下架或编辑后，普通页面下一次刷新曲库时生效；本阶段不做实时推送。
- 更新普通资料不会打断已经加载的音频。
- 下架或删除当前歌曲后，已经打开的页面不强制即时打断；页面刷新曲库时按失效歌曲恢复规则处理。
- 保存资料失败时保留表单输入，允许重试。
- 发布前重新进行必填字段、音频时长、媒体类型、大小和 LRC 格式校验。
- 默认封面、无歌词提示和单个资源错误不得导致整个播放器崩溃。
- 数据目录、数据库、密码配置、会话信息、上传媒体和运行时示范媒体全部加入 Git 忽略规则。
- 不加入开屏、滑入、淡入或其他入场动画，继续支持减少动画设置。

## 8. 响应式与可访问性

- 首页、音乐馆和管理后台覆盖窄屏与桌面布局。
- 所有普通页面为固定底部迷你播放器预留安全空间。
- 表单字段具备可访问名称；错误提示与对应字段关联。
- 上传进度、成功、失败和取消状态既有视觉反馈，也能被辅助技术读取。
- 键盘可以完成登录、编辑、筛选、播放和确认操作。
- 最少验收视口为 390×844、1280×720 和 1920×1080。

## 9. 测试策略

所有功能采用测试驱动方式开发：先建立失败测试，再实现最小功能，最后整理代码。每个实施任务完成后分别进行规格符合性审查和代码质量审查。

### 9.1 服务端与存储测试

- 数据库首次初始化、重复初始化和过渡数据建立。
- 管理密码首次设置、登录、退出、修改和未授权拦截。
- 音频、封面、LRC 类型与大小校验。
- 上传成功、取消、失败、临时文件清理和时长识别。
- 草稿、发布、下架、恢复、回收站和永久删除状态转换。
- 重复歌曲提醒、分类和标签关系、可选来源字段。
- 普通接口只返回已发布歌曲。
- 媒体地址生成、HTTP Range、无效范围和不存在资源。
- 文件清理失败进入待处理状态。

服务端集成测试使用独立临时目录和临时数据库，不写入真实本地数据目录。

### 9.2 前端与播放器测试

- 管理页面首次设置、登录和歌曲管理表单。
- 上传进度、取消、失败重试和表单保留。
- 首页最近加入、精选、直播翻唱精选和每日憨曲。
- 音乐馆歌名搜索、分类筛选、标签筛选和无结果状态。
- 搜索或筛选结果成为临时播放列表。
- 动态曲库更新时按稳定编号保持当前歌曲，避免数组索引错位。
- 刷新后恢复歌曲、进度、音量和队列，但不自动播放。
- 当前歌曲失效时安全回退。
- 今日统计、跨日重置、歌曲计数和憨浓度规则。
- 现有播放、续播、歌词、频谱、快捷键和唱片布局回归测试。
- 加载中、服务异常、空曲库和资源失败状态。

## 10. 最终验收

自动验证：

- 逐阶段运行聚焦测试。
- 最终运行全部前端、服务端和接口测试。
- 运行 TypeScript 类型检查与生产构建。
- 运行差异检查，确认没有意外空白错误或未跟踪的重要源文件。
- 检查提交内容不包含 MP3、M4A、图片、数据库、密码、数据目录、运行时示范媒体、`node_modules` 或其他大文件。

浏览器验证：

- 在 390×844、1280×720、1920×1080 检查首页、音乐馆、管理后台、迷你播放器和完整播放器。
- 确认普通页面内容不被底部播放器遮挡。
- 确认没有重新出现开屏或入场动画。
- 完整执行一次：首次设置管理密码 → 上传单首歌曲草稿 → 补充资料 → 发布 → 普通页面搜索并播放 → 刷新后恢复进度且保持暂停 → 下架 → 回收站恢复 → 再次下架并永久删除。
- 确认音频可以播放、暂停、拖动和自动切换下一首，歌词、频谱、音量、静音和快捷键未回归。

如果应用内浏览器工具不可用或报可信依赖路径错误，不改用未经授权的独立浏览器自动化工具，也不声称浏览器验收成功；保持本地页面运行，并明确列出需要用户手动检查的项目。

## 11. 后续阶段

本阶段完成并验收后，再分别规划：

1. 受限云端测试部署与对象存储，按约 50 元人民币月预算选择中国大陆访问体验合适的服务。
2. Capacitor Android APK 封装与安装包分发。
3. GitHub 登录、邮箱验证码登录、B站 UID 人工验证绑定、账号合并/解绑/找回规则。
4. 故事会切片上传、管理员审核和公开视频详情。
5. 音乐与故事会评论、一级回复、点赞、删除本人内容和举报。

iOS 分发方式待后续单独讨论。普通用户音乐上传保持关闭，音乐始终由管理员后台提供。
