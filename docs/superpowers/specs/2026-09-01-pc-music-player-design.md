# 255留音机 PC 网页播放器设计

## 目标

建立 255留音机的首个 PC 网页版本，先完成可真实播放的音乐播放器体验。页面采用参考视频稳定播放时的唱片、歌词、频谱和控制栏视觉，但不使用开屏模糊、逐渐变清晰或唱片滑出的入场动画。

## 首版范围

- 页面加载后直接呈现最终布局，不播放任何开屏动画。
- 左侧展示方形封面与部分露出的圆形唱片。
- 唱片在播放时匀速旋转；暂停时保持当前位置，继续播放时接着旋转。
- 右侧展示歌曲标题、歌手信息和同步歌词。
- 底部展示频谱、播放进度、时间和播放器按钮。
- 页面底部提供常驻迷你播放器，点击后展开完整播放器，完整播放器可以收回。
- 支持上一首、播放/暂停、下一首、进度拖动、点击跳转、音量和静音。
- 当前歌曲自然结束后自动播放下一首，歌单首尾循环衔接。
- 支持空格键播放/暂停，左右方向键调整进度。

首版不包含账号、云端上传、收藏、评论、管理后台、故事会和移动端手势。这些功能在播放器稳定后单独设计。

## 技术方案

采用 React、TypeScript 和 Vite 构建单页应用。音频由浏览器原生 `HTMLAudioElement` 播放；全局播放器状态统一管理当前歌曲、播放状态、时间、音量和播放队列，迷你播放器与完整播放器读取同一份状态。

项目按以下边界组织：

- `audio-engine`：封装浏览器音频对象、播放命令、进度和结束事件。
- `player-store`：保存队列、当前歌曲、播放状态、音量及界面展开状态。
- `MiniPlayer`：常驻底部，显示当前歌曲和核心控制按钮。
- `FullPlayer`：承载稳定背景、封面唱片、歌词、频谱和完整控制区。
- `Disc`：只负责唱片外观与受播放状态控制的旋转。
- `Lyrics`：解析 LRC，根据当前播放时间选择并滚动到活动歌词。
- `Spectrum`：通过 Web Audio API 获取实时频率数据，只驱动底部频谱。
- `PlayerControls`：统一实现按钮、进度、音量和键盘控制。

## 视觉和动画

完整播放器使用封面衍生的固定柔化背景和深色遮罩，以保证歌词可读。这里的柔化效果从页面出现时就是稳定状态，不进行由模糊到清晰的动画。

封面、唱片、标题、歌词和控制栏首次渲染时均位于最终位置。只有唱片旋转、歌词跟随和音频频谱属于持续播放效果；界面不使用整体节拍缩放、抖动或滑入。

## 歌曲数据

网页使用统一的 `Track` 数据结构：

```ts
type Track = {
  id: string;
  title: string;
  artist: string;
  audioUrl: string;
  coverUrl?: string;
  backgroundUrl?: string;
  lyricsUrl?: string;
};
```

真实内容采用“音频 + 封面 + LRC + 元数据”的组合。首版先放置演示数据和可替换的资源入口，不把用户音频、视频或大体积媒体提交到 Git。

## 与 music-disc-video 的关系

网页会参考 Skill 中的背景、唱片、歌词和进度视觉，但不直接依赖 Remotion 运行时：

- Remotion 帧时间改为 `audio.currentTime`。
- Remotion 唱片动画改为可暂停续播的 CSS 动画。
- Remotion 频谱改为 Web Audio API 的实时分析。
- 开屏模糊和唱片滑出逻辑不迁移。

以后同一套歌曲资源可以同时供网页播放器消费，并交给 `music-disc-video` 生成宣传或歌词视频。

## 状态和异常处理

- 音频尚未准备好时显示加载状态并暂时禁用跳转操作。
- 浏览器阻止自动播放时保持暂停，不重复弹出错误。
- 音频加载失败时在播放器中显示可理解的错误，并允许切换其他歌曲。
- 缺少封面时使用内置占位封面；缺少歌词时显示“暂无歌词”。
- Web Audio API 不可用时隐藏频谱，不影响播放控制。

## 验证标准

- 单元测试覆盖 LRC 解析、当前歌词计算、上一首/下一首循环和时间格式化。
- 组件测试覆盖播放状态切换、进度跳转、音量、静音及完整播放器展开/收回。
- 浏览器检查确认所有可见按钮都能工作，唱片只在播放时旋转，且页面初次打开没有入场动画。
- 生产构建成功，PC 常见宽度下不出现遮挡或横向溢出。

## 完成定义

用户打开网页后能看到 PC 音乐主页和底部迷你播放器；点击后能进入参考图风格的完整播放器，使用所有核心按钮控制一条可替换的演示音轨，并看到唱片旋转、进度变化、歌词同步和可降级的实时频谱。
